# Design: Gnaural schedule `preparse` entry type

**Date:** 2026-05-18  
**Scope:** `GnauralCore/cli/core/GnauralSchedule.pas`  
**Status:** Approved

---

## Problem

The Gnaural schedule format is static XML. There is no way to compute or inject entries programmatically at load time. Some use cases require entries generated by an external tool (e.g., deriving beat frequencies from a live parameter, generating a segment from a state machine).

---

## Solution

Introduce a virtual entry type `type="preparse"` in the `.gnaural` XML format. When the Pascal CLI encounters such an entry while parsing a voice's `<entries>` block, it spawns the specified generator executable synchronously, reads raw `<entry …/>` XML fragments from its stdout, and splices those entries into the voice in place of the preparse entry. Processing happens entirely inside `GnauralSchedule.loadFromFile`, before audio synthesis or any playback command is handled.

---

## XML Format Extension

### Syntax

Inside any `<voice><entries>` block, a preparse entry takes this form:

```xml
<entry type="preparse" generator="mygen.exe"
       parent="0" duration="0.01" volume_left="0" volume_right="0"
       beatfreq="492.8" basefreq="36" state="0"/>
```

### Attributes

| Attribute   | Required | Description |
|-------------|----------|-------------|
| `type`      | yes      | Must be `"preparse"` to trigger generator invocation. |
| `generator` | yes      | Path to the generator executable. Resolved relative to the `.gnaural` file's directory (same rule as PCM voice `description` paths). Drive-rooted absolute paths are accepted as-is. |
| *(others)*  | no       | All remaining attributes are user-defined parameters. Each is forwarded to the generator as `--<name> <value>`. |

Two parameters are always prepended by the CLI regardless of what the XML contains:

- `--gnaural_file <absolute path>` — absolute path to the `.gnaural` file being loaded.
- `--line_no <N>` — 0-based ordinal of this preparse entry within the containing voice's `<entries>` list (the DOM parser does not track source line numbers; the ordinal is the deterministic substitute).

`type` and `generator` are NOT forwarded to the generator.

### Example invocation

For the XML above the CLI calls:

```
mygen.exe --gnaural_file C:\schedules\alpha.gnaural --line_no 2 --parent 0 --duration 0.01 --volume_left 0 --volume_right 0 --beatfreq 492.8 --basefreq 36 --state 0
```

## Generator Protocol

### stdout — generated entries

The generator writes 0 or more self-closing `<entry>` elements to stdout using the standard entry attribute set:

```xml
<entry duration="60" beatfreq="10" basefreq="200" volume_left="1" volume_right="1"/>
<entry duration="30" beatfreq="5"  basefreq="100" volume_left="0.8" volume_right="0.8"/>
```

No XML wrapper element is required. Empty stdout is valid and means the preparse entry produces 0 real entries (the voice simply gets nothing in that position).

### stderr

The generator may write diagnostic text to stderr. The CLI reads stderr in parallel with stdout. If the exit code is non-zero, stderr content is included in the exception message.

### Exit code

- `0` — success; stdout is parsed as XML entry fragments.
- Non-zero — failure; the CLI raises an exception that aborts schedule loading.

---

## Processing Steps (inside `parseVoiceNode`)

1. Detect `<entry>` node with attribute `type="preparse"`.
2. Read `generator` attribute; raise if absent or empty.
3. Resolve generator path:
   - Relative path → `ExpandFileName(FbaseDir + generator)`.
   - Path-traversal check: resolved path must have `FbaseDir` as prefix (same guard as PCM audio).
   - Drive-rooted absolute path → used directly, no base-dir restriction.
   - Raise if the resolved path does not exist.
4. Collect all entry attributes except `type` and `generator` → build arg list as alternating `--name` / `value` strings.
5. Prepend `--gnaural_file <ExpandFileName(aFileName)>` and `--line_no <ordinal>`.
6. Spawn generator via FPC `TProcess` (blocking, capture stdout + stderr).
7. Wait for exit; collect both streams.
8. If exit code ≠ 0 → raise `Exception` with stderr text (or a generic message if stderr is empty).
9. If stdout is empty → done (0 entries generated).
10. Wrap stdout in a temporary XML root `<_>…</_>` and parse via `ReadXMLFile` from a `TStringStream`.
11. If XML parse fails → raise `Exception`.
12. Iterate child nodes of the temporary root; for each `<entry>` element, parse attributes with the existing entry-parsing logic and call `voice.addEntry(…)`.

Multiple preparse entries within the same voice are processed sequentially in document order.

---

## Path Security

| Generator path       | Allowed? | Rationale |
|----------------------|----------|-----------|
| `mygen.exe`          | Yes, if file exists in `FbaseDir` | Relative path, within base dir. |
| `tools/gen.exe`      | Yes, if file exists under `FbaseDir/tools/` | Relative path, within base dir. |
| `../../evil.exe`     | No — exception raised | Resolves outside `FbaseDir`. |
| `C:\tools\gen.exe`   | Yes (absolute) | Same policy as PCM absolute paths. |

---

## Error Propagation

```
GnauralSchedule.loadFromFile
  → parseVoiceNode
    → runPreparseGenerator (raises Exception on failure)
  ← exception propagates

GnauralApp.loadScheduleFile
  ← exception propagates

GnauralApp.runServer (try/except block)
  → emitCommandAck(gctLoad, False, E.Message)
  → writes {"event":"stdio_ack","cmd":"load","ok":false,"error":"..."}

gnaural-session.ts handleAck
  → emitError(aAck.error)
  → existing error UI path (no TypeScript changes needed)
```

## Implementation

### Files modified

- **`GnauralCore/cli/core/GnauralSchedule.pas`** — only file changed:
  - Add `Process` to the `uses` clause in the `implementation` section.
  - Add private helper `runPreparseGenerator(aVoice: TVoice; aEntryNode: TDOMElement; aEntryIndex: Integer; const aGnauralFilePath: string)`.
  - In `parseVoiceNode`, after reading `<entry>` node attributes, check for `type="preparse"` and dispatch to the helper instead of calling `voice.addEntry`.
  - Pass the absolute file path down from `loadFromFile` to `parseVoiceNode` (currently not threaded through; add a parameter or a private field).

### Files not modified

- `GnauralApp.pas` — exception propagation already correct.
- All TypeScript server files — no changes needed.
- `fpc-x64.cfg` — `Process` is part of the FPC standard RTL; no extra search paths required.

## Verification Plan

1. **Build** `GnauralCore/cli/build_x64.bat` — must compile without errors or warnings.
2. **Happy path** — a `.gnaural` file with one preparse entry pointing to a test generator that emits two `<entry>` elements; confirm the loaded voice has exactly 2 entries and playback runs.
3. **Empty output** — generator exits 0 and writes nothing; confirm the voice has 0 generated entries and load succeeds.
4. **Generator error** — generator exits 1 with a message on stderr; confirm `load` ack carries `ok:false` and the error text appears.
5. **Path traversal** — `generator="../../evil.exe"`; confirm load fails immediately with an error, no process spawned.
6. **Generator not found** — generator path resolves but file does not exist; confirm load fails before spawn.
7. **Invalid XML output** — generator exits 0 but stdout is not valid XML; confirm load fails with XML parse error.
